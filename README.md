## 记忆如何工作

- 对话、核心已解析的图像/语音/通知描述、机器人回复与工具感知结果写入原始记录。
- 原版默认：首层达到 100 条，压缩最早 70 条，保留近期上下文；上层达到 4 条，压缩最早 3 条；最高默认 L8，自动触发概率 0.4。
- **层级只表示压缩次数**，不按重要度、用户画像或类别提升层级。读取时按层级与源记录位置确定顺序，修复逆序区域，无需假升层。
- 每个摘要保留时间范围和有序子存档 ID。被压缩的原文永久留存，递归读取可恢复最初经历。
- 永久记忆单独标记为 L100，不参与自动压缩。`Forget` 只移出上下文，仍可读取存档。
- 首次运行接入当前 KiraAI 历史；随后每次请求从归档和近期记录组装持续上下文，持久记忆不因核心短期历史清空而丢失。不改写核心历史文件或请求内已有聊天消息；动态记忆放在当前用户消息之前。
- 归档摘要之外提取事件、事实、偏好、约定、关系、画像、资源与自我认知八个维度。原因、场景、标签、关系三元组和来源都有独立字段。
- 完全相同的事实按会话、实体和内容去重并合并来源；语义合并由异步审计提出，仅允许同会话、同实体、同分类，保留旧版本和证据。

详细原版能力、适配差异和修复依据见 [移植对照](docs/PORTING.md)。

## 安装与配置

在 KiraAI 插件管理中安装本仓库对应分支或插件 ZIP，然后启用。进入侧边栏 **长期记忆·Z**。

核对的 KiraAI 核心版本为 **v2.34.1**，提交 `cad046f7c6a4b071803debe589fb26881ff5fc73`（2026-09-08 的 `xxynet/KiraAI` 快照）。不设置因常规版本更新而阻止加载的 `core_version` 门槛；实际兼容性通过接口测试确认。

压缩模型默认采用 KiraAI 快速模型；审计模型默认采用主语言模型，可分别选择已有模型，无需重复填写密钥。**向量检索默认关闭**：安装、迁移、普通搜索和后台整理均不会为向量解析客户端或发出向量请求。关键词使用 Unicode 子串匹配，检索描述使用本地英文词/中文双字匹配排序，没有向量费用。只有主动开启 `semantic_enabled` 后，才使用可选的向量模型；查询、压缩后索引和手动重建可能产生费用。关闭后旧索引任务跳过，已有向量保留但不参与查询。普通压缩/审计仍可能产生语言模型费用。

所有参数来自同一份严格配置契约。侧边栏直接编辑后原子保存，即时生效；KiraAI 自带插件配置页也会读取生成的 `schema.json`。压缩期间改配置会丢弃旧配置结果，等待下一次整理；改并发数不需要重启。

**升级旧 Z 版：** 新数据保存至 KiraAI 提供的插件数据目录 `alife-v2.sqlite3`，不会覆盖旧版 `memory.sqlite3`。旧版配置保留，新参数位于 `alife` 节。旧版按重要度生成的层级无法当作真实压缩链自动继承，因此不会静默导入或假装迁移成功；升级前应导出旧数据。默认插件和 KiraOS 的安全迁移独立支持，见下节；此处的旧 Z 版数据库不会被冒充为同一种数据格式。

## 安全自动迁移与互斥

默认开启 `auto_migrate` 和 `mutual_exclusion`。启用时只读接入默认记忆的 `data/memory/core.txt`，以及 KiraOS 的 `data/memory/entities/`、`global/` 中的记忆 TOML 和 `profile.json`；不导入技能目录，也不把可重建的向量索引当作来源。

- KiraOS 默认按 `migration_max_chars=120` 过滤：解码后的原始文本超过上限整条跳过，不截断、不拆分超长摘要。画像按既有独立字段/条目检查，不把一段长画像切碎绕过限制。默认插件没有 120 字符限制，仍受 16000 字符单条上限约束。
- 拒绝空内容、占位内容、明显代码/标记输出、控制字符、极端重复文本和不规范字段。TOML/JSON 严格解析（含转义、多行与时区），画像关系进入统一事实契约；迁移不调用任何模型，不声称短文本必然真实。
- 存档、结构化事实和来源凭据在同一事务中保存；保留相对文件路径、内容摘要指纹、原始来源信息、时间依据。未知时间明确标记文件修改时间估算，不伪造原始日期。导入从 L0 开始，不把旧重要度当作压缩层级。
- 相同归属、实体、内容和类别去重，多来源保留凭据；重复迁移不复活用户已删记录、不覆盖人工修改。原内容发生变化会保留为新证据，后续可审计，不把旧来源改写掉。
- 原默认记忆及 KiraOS 全局记忆继续全局可读；用户记忆按号码并入同号码的现有实体，群记忆保留群范围。归属不明的内容保留到待确认范围，仅管理员或显式全局检索可见，不猜成当前用户。旧 `pm` 会话类型规范为 `dm`。
- 成功提交后才通过 KiraAI 原生管理接口停用冲突插件，并再读取一次收尾快照，接住旧插件关闭时写出的最后内容。解析/读写失败时 Alife 暂停，旧插件保持启用；停用后的收尾失败会尝试恢复旧插件，并显示阻塞状态。
- **所有原文件保留，不移动、不删除、不重写**。随时可在核心插件管理中先停用 Alife，再启用原插件。原插件不会自动获得你在 Alife 中新增的内容。若手动重新启用旧插件而 Alife 仍在运行，Alife 自动暂停记忆注入/工具/后台整理，避免反复抢占。

侧边栏概览显示累计导入数、去重/跳过原因、读取错误和互斥状态，可重新检查并迁移。导出包含迁移凭据。KiraOS 的插件停用同时影响其技能路由；如需保留整套 KiraOS，请先切换回原插件。实际用户旧库仍需安装时核对报告。

## 提示词缓存布局

系统区仅增加固定的记忆工具使用规则。所有动态存档、永久记忆内容、用户画像、关系、会话状态与召回提醒都放在本轮用户消息区域、实际用户输入之前，并设置 `persist=False`；压缩模型的人格数据也放用户侧。插件不重写请求内的既有聊天历史。记忆编辑和压缩不会改变插件提供的系统提示内容；这不保证其他插件、核心配置或供应商缓存策略也保持不变。保留核心历史可能与注入的近期记忆有少量重复，以保全历史前缀和角色顺序。

## 主动能力与感知

机器人获得原生工具：

| 工具 | 能力 |
| --- | --- |
| `ReadMemoryArchive` | 默认摘要与分页子存档；include_content=true按需读取完整正文及修改历史 |
| `SearchMemoryArchive` | 本地关键词/词语排序，可选向量排序、层级、时间范围和分页检索 |
| `Memorize` | 主动保存永久核心记忆，并异步归类 |
| `Forget` | 移出永久记忆，保留可读存档 |
| `MemoryOverview` | 感知当前可访问记忆、已知用户、画像、关系、偏好与约定 |
| `CorrectMemory` | 主动按版本号修正摘要，保留原文及旧版本 |

每轮注入会话、参与者、bot 身份、常驻/省略存档数量、可回溯 ID 和结构化事实。省略部分可通过工具继续读取，不以截断后的片段冒充完整记忆。人格化压缩使用 KiraAI 当前人格。多模态识别和消息发送交给 KiraAI 原有适配器；插件不另外启用麦克风、摄像头或桌面监控。

开启“定时主动感知”并填写会话后，插件通过核心 `publish_notice` 唤起机器人，让其依据记忆自主判断是否跟进约定或关心用户。默认关闭，避免安装即向所有会话主动发消息；仅向所列会话触发。具体是否发送、如何发送由 KiraAI 自身工具和消息循环执行。

新安装的 **Bot可访问范围** 默认 `global`，允许跨用户、跨群和私聊回忆；已有配置中明确保存的范围不会被静默扩大，升级后可在侧边栏选择“全局”。全局永久记忆参与常驻上下文，普通跨会话经历按当前话题做本地匹配，附带原会话、用户ID、时间与存档ID。`session` 限制当前会话及迁移共享记忆，`linked` 允许同参与者的存档。后台管理界面是管理员视图。全局可访问不等于所有内容都会自动发送，也不保证模型每次都能正确判断，重要细节应读取原文。

## 2.1 升级与使用

- 数据库仍为 `alife-v2.sqlite3`。第一次升级前以 SQLite 在线备份保存 `alife-v2.pre-v3.sqlite3`，之后只新增名称表和索引，不改写旧摘要、原文或父子链。备份失败会停止初始化；可停用插件后恢复备份回退，备份不包含升级后的新增内容。
- 压缩仍按原版 100/70 与上层4/3规则启动；输入较大时按完整记录缩小批次，超时/连接中断后继续减批重试。最终失败保留原文，自动任务冷却5分钟，手动重试可立即排队。单条特别长时软预算仍可能超出，可换快模型或提高超时。
- `认为/觉得/说` 等不完整谓词不再作为人物关系接收。旧关系原样留存，界面标为待审校、关系图与Bot关系投影排除这条连线；审计可依据来源修正或清除连线。过滤只排除明显结构问题，并不代替事实核验。
- 名称来自新消息的昵称/会话标题；以稳定ID关联现名、曾用名、来源和观察时间，不合并同名用户。人物与群名页面可手动审校，或按已知ID调用当前 OneBot 适配器更新。未知适配器、无法确认的平台和不存在的ID不猜测；旧 `user:数字` 可先手工补称呼，不自动改成QQ身份。
- Bot可用 `MemoryNames` 查询现名/曾用名，`CorrectMemoryName` 有依据地更新称呼，`RefreshMemoryName` 从支持的适配器查询。历史原文保持当时写法；显示标签是当前称呼，名称历史可回看。
- 删除使用页面内确认，兼容 KiraAI 的 iframe 沙箱。软删除的记录不再检索，仅以它为证据的事实也停用；已生成的父摘要仍保留，可单独审校。修改历史和导出中仍保留原始数据。
- 页面增加关系/维度星图、聚焦与证据入口、柔和动效，遵循系统减少动画设置。HTML、JS、CSS、图标变化均触发刷新；配置、记忆和名称编辑草稿可恢复。
- “导出完整记忆”在侧边栏内显示完整JSON，可复制后保存为文件，包含名称历史；独立打开页面时也提供直接下载，避免嵌入页阻止下载而没有反馈。

例如：阿澄在A群说“周末去猫咖”，后来小夏在私聊问“之前说的猫咖呢？”——全局召回按“猫咖”等本地词语找到A群存档，标明是阿澄、发生时间和原会话；Bot可以读取原文后说“阿澄之前在A群提过…”，不应误说成“小夏你说过…”。查询曾用名“小明”仍会找到同一稳定ID及其现名“小夏”，同名的另一个账号则保持独立。

## 实时侧边栏

记忆概览、存档管理、画像关系、后台任务、偏好设置五个页面；支持明暗主题、移动窄屏、键盘操作和图标复用。

- 数据与任务自动刷新，无需重启。
- 页面内容文件变化后自动重载，保留配置草稿及已打开记忆的编辑草稿。
- 配置有版本指纹，记忆有递增版本号。后台与人工同时修改时返回冲突，保留草稿，不覆盖新数据。
- 原始内容不可原地篡改；用户可修正展示摘要，审计版本保留。关系、实体、分类、标签、原因和场景都可编辑。
- 删除为软删除，修改历史保留；删除一条记录不会自动清除其他关联归档。`Forget` 与删除分开。
- 导出包含记录、父子关系、归类事实、修改历史和迁移凭据的完整 JSON。数据库也可使用标准 SQLite 工具读取。

## 规范化与异步处理

模型只允许输出契约规定的 JSON 对象。Markdown 围栏、前后解释、重复键、非法类型、未知字段、NaN、未知类别与不存在的来源全部拒绝。默认重试两次；仍失败则任务失败，原文与原存档不变。不会从解释文本中提取大括号、自动补造字段或退化成自由文本存储。

严格结构能保证**写入格式与引用约束**，不能保证模型对事实的理解永远正确。归类与审计必须保留证据；人工可核对、修正，模型不得靠缺失的证据强行合并。

后台任务持久化去重，最多四个工作槽，默认两路并发。数据库操作在线程中执行，模型调用异步且有超时。停用/重载会取消并回收工作任务，未完成任务恢复为排队。每次压缩在同一事务中创建摘要、关联子存档、更新上下文和归类事实；输入被人工修改时整个提交失败，不留下半成品。
