# 2.2.0：迁移身份合并与界面动效

## 目标与边界

旧 KiraOS/默认记忆按实体目录导入时，会生成 `legacy:user:123`、`legacy:group:qq:456`、`legacy:global` 这类合成标识。它们不是真实账号，也不应该长期以“旧插件档案”的形式存在。本轮把这些标识按号码并入真正的实体；无法确定的保留为明确的占位并自动重试。不重写原始文件、不重新导入、不调用模型。

## 身份解析规则

| 旧标识 | 结果 |
| --- | --- |
| `legacy:user:<平台>:<号码>` | 同号码现有用户优先，否则带平台前缀的 `<平台>:<号码>` |
| `legacy:user:<号码>` | 同号码现有用户 → 唯一在线适配器 → `unresolved:user:<号码>` |
| `legacy:group:<平台>:<号码>` | 同号码现有群会话优先，否则 `<平台>:gm:<号码>` |
| `legacy:group:<号码>` | 同号码现有群会话 → 唯一在线适配器 → `unresolved:group:<号码>` |
| `legacy:global` | `global`（kind=global，全局记忆桶） |
| `legacy:self` | `self`（kind=self，机器人自身桶） |
| 无号码且无会话 | `unscoped`（未分类 · 来源会话未确定） |

- 同号码存在多个平台实体时**不合并**，保留候选并在状态接口报告；绝不猜测平台。
- 用户档案并入该账号的私聊会话 `<平台>:dm:<号码>`，群档案并入 `<平台>:gm:<号码>`，群聊与私聊保持区分。
- 合并时把旧实体的名称历史整体迁移到目标实体（旧名成为曾用名），再删除旧实体行；目标已有现名时不覆盖。
- 规范化后重算事实指纹，指纹相同的事实合并来源与标签并保留版本记录。

## 存量数据与幂等

- 启动时若检测到合成标识，就在事务内重写 `records.sid/users`、`facts.sid/subject/relations` 与指纹；`event_key`、`migration_items` 凭据保持不变。
- 迁移摘要仍按**原始**标识计算，与 2.1.1 逐字一致，升级不会重复导入（测试 `test_canonical_identity.py` 与基线脚本比对验证）。
- 一次运行只处理仍然合成的行；重复运行结果不变。适配器在启动后才连上时，首次对话会补跑一次。
- 数据库 `user_version` 提升到 4（仅语义标记，无表结构变更）。

## OneBot 名称查询

`RefreshMemoryName` 与人物页的“按账号查询”支持裸号码：先试当前会话适配器，再试标识前缀，最后遍历已安装适配器。人物用 `get_user_info`（陌生人信息），群用 `get_group_info`。查询成功后若标识仍是合成占位，会立即绑定并合并。

## 界面

- 记忆星图新增缩放滑条（50%–250%）与滚轮缩放（以光标为中心），切换模式与翻页保持缩放。
- 会话、层级、维度下拉选择后立即重新加载；按钮只保留给关键词/主题文本搜索，回车同样生效。
- 刷新默认自动（按钮带旋转指示），点击一次切换为手动，再点一次立即刷新并恢复自动；选择保存在浏览器本地。
- 同色系的过渡、悬停、进场与背景光晕动效；系统开启“减少动态效果”时全部停用。
- 品牌区动漫图标与 KiraAI 主侧边栏图标均未改动。

## 验证

- 新增 `tests/test_canonical_identity.py`：号码合并、唯一适配器绑定、多平台歧义保护、global/self 拆桶、名称迁移、跨桶重复事实合并、强制绑定、标签措辞、摘要稳定性。
- 原有 5 个测试文件全部通过；迁移摘要与 2.1.1 逐字比对一致。
- 浏览器以真实 `app.js` + 模拟接口验证：筛选即选即生效、自动/手动刷新切换、星图缩放与滑条同步、名称页标签。
