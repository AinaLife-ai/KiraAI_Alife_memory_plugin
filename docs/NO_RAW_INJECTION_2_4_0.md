# 2.4.0：原始对话不再重复注入

## 问题（实测）

宿主 KiraAI 的会话历史本身就是「最近 N 轮原文」（`session_manager.py:251`，`max_memory_length` 默认 50 轮，超了从头部硬砍）。而我们在每轮记忆块里又把**还没压缩的原始记录（L0）**按"最近优先"注入了一遍：

| 状态 | 注入块 | 其中与宿主历史重复 |
| --- | --- | --- |
| 压缩前（60 轮会话） | 22.6 KB（120 条 L0） | 100 条 / 3.9 KB |
| 压缩后 | 9.8 KB（1 条 L1 + 50 条 L0） | 50 条 / 2.0 KB |

即：模型同时看到了**原文（宿主）+ 原文副本（我们）+ 摘要（我们）**。这是 Alife 原版没有的问题——在原版里「聊天历史 = 存档树」，压缩是**原地替换**，不存在重复；我们移植后「历史归宿主、树归我们」，注入就变成了追加。

## 改动

- 新增配置 `inject_recent_raw`（默认 **关**）：L0 不再进入每轮常驻记忆块；
- 记忆块现在只装：**压缩存档（L1+）+ 结构化事实 + 跨会话相关 + 人物/群名**；
- L0 的入口改为按需：`SearchMemoryArchive`（主动检索）、`ReadMemoryArchive(id)`（按 ID 读回）；跨会话被动召回不受影响（其他会话的相关内容照常带入）；
- 想恢复旧行为：把 `inject_recent_raw` 打开。

### 效果（同一场景实测）

| | 改动前 | 改动后 |
| --- | --- | --- |
| 压缩前注入块 | 22.6 KB | **0.3 KB** |
| 压缩后注入块 | 9.8 KB | **0.46 KB** |
| 与宿主历史重复 | 100 / 50 条 | **0 条** |

## 为什么不改成"写回"（类似 ADS）

考虑过让插件也接管上下文压缩（压缩后写回宿主历史，保留最近 N 轮）。放弃的原因：

1. **职责重叠**：ADS / Context Condensation / KSM 已经在做这件事，写回会和它们抢着改写 `req.messages`，需要额外的互斥仲裁；
2. **Alife 的写法是"原地替换"**（`MemoryManager.SaveMemory` 插入摘要节点后 `RemoveRange` 删除原文），在 KiraAI 里等于改写宿主历史——和我们「外挂式记忆插件」的定位相反；
3. **收益可以由"不注入"拿到**：重复的根源是我们把宿主已有的东西又注入了一遍，不注入即可，无需改历史。

## 提示词缓存

记忆块挂在**最后一条用户消息**里（与宿主自己的 `sessions/time` 动态块同处），`persist=False`，所以：

- 系统提示 + 历史前缀保持逐字节稳定；
- 每轮"未命中尾巴" = 上一轮动态块 + 我们的记忆块 + 上一轮用户消息。实测对照组显示：**即使完全不注入我们的块，分歧点也一样**（都在宿主 `<system_reminder>` 处），所以我们只贡献了自己块的体积——而它从 22.6 KB 降到了 0.3 KB。
