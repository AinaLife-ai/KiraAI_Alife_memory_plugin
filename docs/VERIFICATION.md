# 验证记录

环境：Windows、Python 3.12、Pydantic 2.13；KiraAI v2.34.1，固定核心提交见 PORTING.md。

最终本地结果：**32 项测试通过，7 个参数化子场景通过**；Ruff 静态检查、JavaScript 语法检查和 `git diff --check` 通过。

已执行：

- 数据与引擎回归：原文保留、父子溯源、级联、逆序区域、同秒唯一ID、重复事件、编辑竞态事务回滚、永久记忆移出后读取。
- 检索与分类：Unicode关键词、时间交集、分页总数、会话范围、向量模型隔离、未知来源拒绝、同实体合并保留证据、跨实体合并拒绝。
- 结构化输出：围栏、前后解释、重复键、额外字段、缺字段、类型漂移、NaN均拒绝；有界重试；配置错误拒绝。
- 后台：任务去重、单次认领、重启恢复、取消重排队、配置变化放弃过期提交。
- 停用时等待 SQLite 工作线程真正完成，避免协程已取消但数据库句柄仍占用的竞态；另有确定性阻塞线程测试。
- 真实KiraAI类集成：插件导入和注册、KiraMessageBatchEvent捕获、LLMRequest上下文与非持久注入、原生工具、管理员API配置原子保存、记忆409冲突及422校验。
- 安全迁移：120/121 字符边界、默认插件长文本保留、多行/转义/时间戳、来源文件逐字节哈希不变、两次导入去重、多来源凭据、人工删除不复活、阈值调整重试、事务注入故障回滚、共享范围压缩后不丢失。
- 互斥：先提交后停用、解析错误保持旧插件、收尾快照失败恢复旧插件、手动切回旧插件后 Alife 让位。使用真实核心类与受控插件管理器替身，不声称完成生产插件生命周期验收。
- 缓存：修改永久记忆并增加感知后，两次真实 LLMRequest 的 system 内容及已有聊天消息完全一致，动态内容只出现于末尾 user 区域且先于本轮输入。
- 默认无向量：客户端解析入口设置为调用即报错，搜索/索引/遗留重建任务均通过；关闭时管理员重建接口拒绝排队。本地词语检索过滤无关项。
- 可选向量：显式开启后能生成索引；请求进行中关闭后丢弃返回向量，不写入过期索引。
- JavaScript语法检查。
- 浏览器：本地真实插件API + 合成演示数据，配置保存立即生效；记忆详情、编辑器与原文入口；修改前端文件后自动重载，未保存编辑草稿恢复，并成功保存到存档列表。
- 本次浏览器补测：默认/KiraOS 迁移共 3 条合成记忆、超长跳过 1 条的报告；重新迁移按钮可用；默认向量开关关闭且模型选择禁用，勾选后可选，关闭保存后向量重建按钮禁用。

测试模型为确定性夹具，不调用用户的生产模型或聊天适配器。**未执行**：真实模型质量/成本评估、真实QQ/Telegram等端到端主动发送、目标用户已有记忆库迁移、与原版同硬件性能对比。界面是在本地验证宿主中运行；KiraAI整套管理端的实际嵌入部署仍需安装验收。
