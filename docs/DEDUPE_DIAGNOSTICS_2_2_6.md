# 2.2.6：永久记忆合并的诊断信息

## 问题

点「合并相似永久记忆」后任务 0.0 秒就显示完成、却没有合并。原因是 `consolidate` 在两种情况下会立刻返回，而任务详情当时是空的，看不出为什么：

1. 该会话**常驻**永久记忆不足 2 条（可能已被自动合并，或已被 Forget / 冷归档）；
2. 本地相似度**未发现相似簇**（`dedupe_threshold` 默认 0.25）。

## 改动

`consolidate` 现在返回并写入任务详情：

```
常驻 3 条 · 相似簇 1 个 · 合并 1 簇 · 保留 0 簇
常驻 1 条 · 相似簇 0 个 · 合并 0 簇 · 保留 0 簇 · 该会话永久记忆：常驻 1 条、已归档 2 条（归档的需先恢复常驻才会参与合并）
常驻 2 条 · 相似簇 0 个 · 合并 0 簇 · 保留 0 簇 · 未发现相似簇（阈值 0.25）
```

后台任务页的列表会直接显示这段文字（任务类型显示为「永久记忆合并」），日志同样打印。

## 自动路径

- 启动后第一次调度、以及之后每 `audit_interval`（默认 1800 秒）一次，对所有**常驻永久记忆 ≥2 条**的会话入队 `dedupe`；
- 每次 `Memorize` 成功后也会立即入队一次（同会话去重 + 失败冷却 5 分钟）；
- 与手动按钮走同一条 `consolidate` 逻辑，因此现在同样会留下诊断详情。

## 验证

- `tests/test_permanent_dedupe.py`：无相似簇时报告 `clusters=0` 且提示「未发现相似簇」；合并后再跑提示「常驻 1 条、已归档 2 条」。
- 端到端：第一次 `{permanent:3, clusters:1, merged:1}`，第二次 `{permanent:1, clusters:0, note:"常驻 1 条、已归档 2 条"}`。
- 全量 `pytest tests/`：**76 passed, 1 skipped, 7 subtests passed**。
