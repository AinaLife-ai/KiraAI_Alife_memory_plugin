## 层级 bug

原始 `MemoryManager.Filter` 假定从高到低扫描连续层级。当低层之后出现高层时，单条分支直接改元数据层级，另一分支仅压缩前方区域并提前返回；可能形成“未经历压缩却被升层”的状态。上游 `Tests/Alife.Test.Memory/MemoryManagerTests.cs` 给出了单条逆序、多条逆序、正常单调及反复逆序的回归场景。

移植采用显式 `level`、`permanent`、原始 `position` 和父子边。每次规划从规范序列选择同层最早记录；无论输入物理顺序如何，都不会跳过同层记录或把重要度当深度。真实压缩才创建 `level+1`，原来的记录不改层级；保存返回唯一ID，不再依赖秒级时间范围充当唯一键。

这是一种保持语义的修复，不是逐行复制上游的错误分支。测试覆盖上述四类结构及真实多层级联。

## 有意的适配差异

- C# SemanticKernel/DuckDB/本地 BGE 改为 KiraAI 原生 provider 与 Python SQLite，无新增常驻服务或模型下载。
- Alife 桌宠的唯一会话适配为 KiraAI 的每会话持久上下文；跨会话权限由明确配置控制，默认隔离。
- 原版纯文本摘要改为严格JSON中的 `summary` + 有来源的归类事实，保持叙事摘要，增加机器校验。原始事实不会因分类失败而被吞掉。
- 原版文本文件镜像改为完整JSON导出及SQLite可读存储，避免数据库与文件双写不一致。逐层读档工具保持相同能力。
- Alife其它插件的桌面截图、音频采集和自主玩耍不属于 MemoryService；KiraAI已有适配器与主动代理承担这些输入/行为，记忆插件接入其感知结果。
- 不继承旧Z版根据重要度升层、定期删原文、宽松解析模型响应、自动禁用其它插件等实现。

## 优化边界

固定并发、任务去重、索引过滤、SQLite线程隔离、事务冲突检测、同一事实来源合并，减少重复模型请求及同步阻塞。向量相似度在过滤后的SQL查询中计算，不把全库记录搬到Python排序。仍是精确扫描候选向量，不声称百万级ANN性能。未运行与C#/DuckDB实现的同硬件基准，不宣称具体加速倍数。
