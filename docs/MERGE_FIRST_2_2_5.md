# 2.2.5：相似永久记忆优先合并

## 背景

2.2.3 的 `dedupe` 默认保守：只有"同一对象 + 同一件事/属性 + 互为重复或更正"三条同时满足才合并。实际使用中，同一份名单被三次补充（每次多一点细节）时，模型会判定"合并会丢信息"而选择保留，于是三条永久记忆继续每轮常驻。

## 改动

新增配置 `dedupe_merge_first`（默认 **开**）：

- **开启**：提示词改为"默认选择 merge"——只要这些记忆围绕同一个对象或同一主题（同一份名单、同一个约定、同一件事）就合并成一条，把各条**独有的关键信息全部并入 content**（可以比原来长），原样保留人名、群名、数字、QQ 号与日期；只有主体或对象明显不同（阿远 vs 小夏）才 keep；互相矛盾以时间较晚的说法为准并说明是更正。
- **关闭**：回到 2.2.3 的保守提示词（确属重复或更正才合并）。

其余机制不变：本地包含度成簇（阈值 `dedupe_threshold` 默认 0.25）、审计模型裁决、保留最新一条并更新其 summary、其余 `cold=1`（原文与版本保留，可一键恢复常驻）、独立任务通道不占 `worker_count`。

## 验证

- `tests/test_permanent_dedupe.py` 新增：开关开启时提示词含"默认选择 merge"，关闭时含"只有同时满足三条才 merge"。
- 全量 `pytest tests/`：**75 passed, 1 skipped, 7 subtests passed**。
